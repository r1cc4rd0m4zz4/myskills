# Global Guardrails: Code Is Law (Anti-Bloat Mode)

> *"Perfection is achieved, not when there is nothing more to add, but when there is nothing left to take away."* — Antoine de Saint-Exupéry  
> Every superfluous line is an uninspected law, a hidden failure state, and an expanded attack surface.

- **Code Is Law (Zero Trust):** Code is law, not promises or reputation. Audit actual implementation, privileges, and blast radius directly from verbatim source—never trust documentation, claimed intent, or opaque AI output. Zero black-box diffs: if you cannot explain every line at the runtime layer, delete it.
- **Git Workflow:** NEVER push autonomously (even when a skill such as `/wayfinder` instructs to push a branch)—wait for the explicit order ("push", "fai il push", "pusha"). Before editing in a repo, read its own `AGENTS.md`/`CONTRIBUTING.md`. Before proposing any commit or push, run `git fetch` + `git status -sb`, report the exact divergence, and run the repo's verification gate.
- **Notes & Runbooks:** Keep `git status` clean. Save personal notes, runbooks, and unrequested `.scratch/` or research artifacts in local private storage outside tracked repository history (or gitignored).
- **The Ladder (Minimal Entropy & Lateral Thinking):** Solve the problem with the least state, context hops, and new code—invert the problem before adding machinery.
  1. *Invert & Eliminate:* Reframe the question: what assumption can we drop so the problem disappears? Reject unrequested options, speculative config, and "for later" flexibility.
  2. *Data & State First:* Shape data so control flow stays trivial; make invalid states unrepresentable at the interface/seam.
  3. *Reuse & Native:* Reuse existing repo code -> then OS primitives, runtime built-ins, and stdlib. Probe flags and APIs against the live target (`--help`, `man`) before use—never assume phantom options exist.
  4. *Lockfile-Only Dependencies:* **NEVER** add an external dependency without explicit pushback and user approval.
  5. *Inline Locality:* Keep control flow flat and local inside deep modules. Never extract single-use helpers, shallow pass-through wrappers, or premature abstractions; deletion beats addition.
- **Pushback Policy:** Direct minimal execution by default. Mandatory proactive pushback before acting ONLY when a request introduces new external dependencies or an architecture grossly oversized relative to platform standards.
- **Devil's Advocate Grilling:** Whenever `grilling` runs (directly or via `/grill-*`, `/wayfinder`, `/triage`, `/improve-codebase-architecture`, `/plan`) or during planning, every question round MUST include an explicit Devil's Advocate counter-option: challenge the orthodox path via problem inversion and The Ladder (Level 1–5), exposing hidden assumptions, blast-radius risks, and cognitive blind spots—including a radical paradigm shift when a 10x simpler asymmetrical path exists.
- **Trust Boundary & Shell Hardening:** Treat external inputs, env, and callers as untrusted—validate strictly at the trust boundary. No security theater: match tools to the actual stack (zero SCA on zero-dependency code); no reachable PoC = no bug (reject speculative patches for static noise). **When writing shell/installers:** enforce atomic `trap` cleanup on `INT TERM EXIT`, pass ShellCheck + Gitleaks, and make installers work both locally from any dir (`BASH_SOURCE[0]`) and via pipe (`curl | bash`) without assuming a public repo.
- **Verification, Singularities & CI:** Compact code without checks is unverified debt. Test input/state singularities (empty, max, malformed, interrupted) at the seam and negative branches before the happy path. When CI exists, actively query remote jobs until green (`success`) before calling it done—local pass != remote verification.
- **Engineering Skills & Spec Wiring:** Unless the repo specifies otherwise, default all engineering skills (`/to-spec`, `/to-tickets`, `/implement-spec`, `/code-review`, `/triage`, `/wayfinder`) to local markdown in `.scratch/<slug>/` (`spec.md`, `issues/NN-<slug>.md`, `map.md`; canonical labels: `ready-for-agent`, `needs-triage`, `needs-info`, `ready-for-human`, `wontfix`; single-context `GLOSSARY.md` + `docs/adr/` created lazily only when domain-modeling runs) without requiring `/setup-matt-pocock-skills`. In `/to-spec`, replace verbose Agile "As a user..." ceremony with concise verifiable behaviors, state contracts, and a single high-level testing seam.
- **Sanitization:** Write strictly production-grade commits, code, and docs using canonical domain terminology—strip all personal paths, usernames, and conversational/internal labels.
